# ndvi-gapfill

ML-часть решения по восстановлению вегетационного индекса NDVI и выделению
негативных периодов вегетации на сельхозполигонах.

Две точки запуска, обе на одном пакете `vegetation_ml`:

* **пакетный инференс** — файл организаторов → `submission.csv`, без веба и без
  HTTP;
* **HTTP-сервис** — `POST /v1/analyze` и `GET /readyz` по контракту Go ↔ ML
  (v1 и расширение v1.1) для веб-сценария с новым полигоном.

## Результат

Локальная проверка на искусственной маске по всем выданным файлам, метрика
регламента `Gap Score = round(30 * max(0, 1 - RMSE / 0.10), 2)`. Протокол
повторяет реальную подачу: отобранные контрольные строки скрыты всегда — их
значения не попадают ни в обучение, ни в признаки.

| набор контрольных строк | baseline организаторов | наше решение |
|---|---|---|
| все (9208) | RMSE 0.0944 → 1.69 балла | **RMSE 0.0634 → 10.98 балла** |
| полигоны `train_dataset` (4958) | RMSE 0.0912 → 2.64 балла | **RMSE 0.0573 → 12.80 балла** |
| полигоны `test_features` (2170) | RMSE 0.1019 → 0.00 балла | **RMSE 0.0716 → 8.51 балла** |

Разброс между группами — свойство данных, а не модели: у полигонов
`test_features` разность наблюдений, отстоящих на ≤2 дня, равна 0.1060 против
0.0956 у `train_dataset`, то есть шум измерения примерно на 11% выше. Baseline
организаторов на этом наборе даёт ровно 0 баллов.

Это **локальная** оценка. Официальный результат платформы по скрытым
контрольным строкам не получен и этими числами не подменяется.

Разбор данных, метода, экспериментов и ограничений — в
[reports/research.md](../../reports/research.md).

## Данные организаторов

Три файла дополняют друг друга и не пересекаются по ключу «полигон + дата»:

| файл | полигонов | период | контрольных строк |
|---|---|---|---|
| `train_dataset.csv` | 39 | 2010–2024 | — |
| `test_features.csv` | 20 | 2010–2024 | 2323 |
| `private_features.csv` | 78 | в основном сезон 2025 | 3112 |

Все три используются как общий контекст: открытые наблюдения любого файла
годятся и для обучения, и для сезонной нормы, и для эффекта даты. Обучение по
всем файлам вместо одного `train_dataset` даёт +0.4 балла на контрольных
строках. Контрольные строки в обучение попасть не могут — их значение
отсутствует, а маскируются только известные наблюдения.

В `test_features.csv` нет колонок `ndvi_climatology_mean` и
`ndvi_climatology_std`; на решение это не влияет, сезонная норма считается
самостоятельно.

## Стек

Python 3.14, numpy, pandas, scikit-learn (`HistGradientBoostingRegressor`),
FastAPI + uvicorn + pydantic для HTTP, pytest для проверок. Полный список с
зафиксированными версиями — `backend/ml/requirements.txt`.

## Запуск

### Пакетный инференс

```bash
# ответ по test_features.csv
python -m vegetation_ml.cli --private ../../data/test_features.csv predict \
       --context ../../data/private_features.csv \
       --out ../../submission_test.csv

# ответ по private_features.csv
python -m vegetation_ml.cli --private ../../data/private_features.csv predict \
       --context ../../data/test_features.csv \
       --out ../../submission.csv
```

Команда запускается из `backend/ml/`. `--private` задаёт файл, чьи контрольные
строки нужно восстановить, `--context` — остальные файлы организаторов: они
используются и как контекст ряда, и как дополнительные обучающие примеры.

Обучение занимает около 6 минут, артефакт сохраняется с манифестом. Ответ
пишется с заголовком `anon_polygon_id,date,primary_ndvi_pred`, и множество
ключей проверяется на точное совпадение с контрольными строками **до** записи
файла: пропущенные, лишние и дублирующиеся ключи, NaN и неверный заголовок
приводят к ошибке, а не к тихой записи некорректного ответа.

Если артефакт уже существует, обучение пропускается.

Отдельно:

```bash
python -m vegetation_ml.cli train
python -m vegetation_ml.cli validate
python -m vegetation_ml.cli analyze --polygon AOI-0001 --season 2025
```

### HTTP-сервис

```bash
python -m vegetation_ml --host 0.0.0.0 --port 8000
```

Проверка готовности и запрос анализа:

```bash
curl -s http://127.0.0.1:8000/readyz
curl -s -X POST http://127.0.0.1:8000/v1/analyze \
     -H 'Content-Type: application/json' --data @request.json
```

Сервис держит **один вычислительный слот** без внутренней очереди: параллельный
запрос получает `429 busy`. Слот удерживается до фактического окончания расчёта,
даже если клиент уже ушёл по тайм-ауту, поэтому второй расчёт не запускается.
`GET /readyz` отвечает и во время расчёта.

Порт на хост в Compose не публикуется, Go обращается по `http://ml:8000`.

#### Два профиля признаков

| профиль | версия схемы | что передаётся | что применяется |
|---|---|---|---|
| `ndvi-weather-v1` | 1.0 и 1.1 | итоговый NDVI и погода | резервный метод, RMSE ≈ 0.085 |
| `ndvi-multisensor-v1` | только 1.1 | плюс значения сенсоров, культура и ряды соседних участков | обученная модель, RMSE ≈ 0.063 |

Расширенный профиль объявляется в `/readyz` **только при загруженном артефакте**
модели; запрос необъявленного профиля отклоняется как `unsupported_contract`.
Путь к артефакту задаётся переменной `VEGETATION_ML_MODEL`, по умолчанию
`artifacts/restoration.pkl` от корня монорепозитория.

Расширение аддитивное: клиент версии 1.0 продолжает работать без изменений.
Поля, лимиты и правила применимости production описаны в
[каноническом контракте](../../.agent/contracts/go-ml-http.md); расширение v1.1
подключается только после согласования этапа из
[плана интеграции](../../.agent/plans/ml-integration.md).

## Как устроено решение

`primary_ndvi` собран из трёх сенсоров с разной калибровкой в порядке
s2 → landsat → modis. Разница между ними (до 0.085 по среднему) даёт бо́льшую
часть «скачков» ряда, а не изменение вегетации. Отсюда три шага:

1. **опорная оценка** — снятие калибровочного смещения сенсора, слияние
   доступных в один день сенсоров и сглаживание ряда гауссовым ядром вместо
   двух соседних точек; к результату добавляется ожидаемое смещение сенсора,
   вычисленное по сеткам пролётов спутников;
2. **бустинг на остатке** от опорной оценки, а не на самом значении — при
   отсутствии сигнала результат не становится хуже опорной оценки;
3. **эффект даты** — общий сдвиг наблюдений остальных полигонов в тот же день;
   по абляции это самый весомый признак после опорной оценки.

Обучение идёт на искусственно скрытых наблюдениях всех выданных файлов с тем же
профилем масок, что применили организаторы (измерен по `private_features.csv`:
2252 серии длины 1, 340 длины 2, далее единицы длиной до 5).

## Ограничения

* Все приведённые метрики — локальные, на искусственной маске. Результат
  платформы не получен.
* Обученная модель доступна по HTTP только в профиле `ndvi-multisensor-v1` и
  только при достаточной истории участка (не менее 60 надёжных наблюдений и
  2 сезонов). В остальных случаях работает резервный метод, и ответ сообщает об
  этом в `limitations`; поле `method` всегда говорит, чем восстановлена точка.
* Без переданных соседних участков (`peers`) эффект даты не используется, и
  качество восстановления по HTTP ниже пакетного режима.
* Восстановленная моделью точка не считается независимым наблюдением: период,
  собранный только из восстановленных значений, получает статус `candidate`, а
  не `confirmed`.
* Погодная гипотеза выдаётся вместе с наблюдаемыми основаниями и помечается как
  неподтверждённая. Уборка урожая, смена культуры и остаточная облачность
  объясняют тот же спад.
