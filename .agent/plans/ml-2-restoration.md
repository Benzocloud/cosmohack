# План ML: восстановление NDVI и аномалии

Владелец: ML-разработчик, бывший Backend №2. Область: `backend/ml/vegetation_ml/`,
`backend/ml/tests/`, Python-зависимости, пакетный инференс, два входа анализа и
`reports/research.md`. B4 встраивает пакет в Go, Docker и общий образ; B3
согласует API и хранение; B1 отвечает за физический смысл источников;
frontend показывает результат. Сетевого ML-сервиса не создаём: Go запускает
ограниченный Python subprocess.

Основание: [требования организаторов и решения команды](../requirements.md), [постановка организаторов](https://xn--d1ari.xn--80aa2abijcbdyq6a.xn--p1ai/storage/docs/doc-1788536456.pdf),
[критерии оценки](https://xn--d1ari.xn--80aa2abijcbdyq6a.xn--p1ai/storage/docs/doc-1788536476.pdf).
Общий порядок журнала, двух ревью Sol, исправлений Luna, личной проверки,
апрува человека и публикации описан в [общих инструкциях](../instructions.md);
здесь он не дублируется. Все этапы ниже имеют статус `planned`; nickname,
ветка, SHA, проверки и апрув пока не назначены. Для каждого этапа действует
согласованное имя backender-ветки из общих инструкций.

Публичный веб-анализ и пакетный режим используют общие функции, но имеют два
отдельных входа: веб-адаптер получает ряд нового полигона, пакетный принимает
`private_features.csv`. Доступность признаков и провайдерское сопоставление
`primary_ndvi` описываются явно для каждого входа. Не восстанавливать географию анонимных полей догадками и не получать скрытые
правильные значения. Происхождение климатологии проверять, неизвестность отмечать.

## ML-01 — контракт, маскирование и проверка данных (0–2 ч)

**Статус:** planned

**Владелец:** ML, с B1/B3/B4. **Зависимости:** общие типы и требования.

- [ ] Описать ключ `anon_polygon_id + date`, дату `YYYY-MM-DD`, `primary_ndvi`,
  `is_synthetic_gap`, обязательные поля пакетного режима и JSON-структуру веб-анализа.
- [ ] Зафиксировать reference train как заявленные 99 955 строк до проверки
  файла. Train-only `ndvi_zscore` и `status` не являются признаками инференса.
- [ ] Для `is_synthetic_gap=True` маскировать `primary_ndvi` и все динамические/производные
  признаки этой строки, затем пересчитывать зависимые признаки. Ближайшие
  известные значения слева и справа оставлять для разрешённой ретроспективной
  интерполяции; отдельный ранний режим не использует будущие даты.
- [ ] Проверить фактическую схему и полный состав маскируемых колонок, когда CSV
  будет выдан. Не считать заявленные поля доказанными до чтения файла.
- [ ] Зафиксировать провайдер `primary_ndvi`, доступные признаки и версии
  зависимостей без выдумывания отсутствующего происхождения данных.

**Локальная готовность:** есть контракт, синтетическая фикстура и проверка правил
маскирования, на которых могут работать ML-02 и B4. **Доказательство на данных:**
схема, число строк и состав маски подтверждены только после получения CSV;
отсутствие файлов записывается как блокирующая зависимость и не маскируется
результатом фикстуры.

## ML-02 — базовый метод, валидатор и прототип анализа (2–6 ч)

**Статус:** planned

**Владелец:** ML. **Зависимость:** локальная часть ML-01; B4 может подключать
прототип к реальному сквозному пути к 12-му часу.

- [ ] Реализовать baseline как среднее ближайших известных значений до и после
  gap, без весов. Для полностью пропавшего полигона и края ряда задать конечный
  fallback и причину ограниченности; веб может отказаться от вывода при
  недостаточном контексте.
- [ ] Реализовать пакетную команду и строгий валидатор: заголовок ровно
  `anon_polygon_id,date,primary_ndvi_pred`, UTF-8, comma, ISO date, конечные числа.
  Множество ключей должно точно совпадать с контрольными ключами входа: выявлять
  пропущенные, лишние и дублирующиеся ключи; строки только с естественными пропусками не включать.
- [ ] Добавить простой z-score относительно той же сезонной фазы для первого аномального поля,
  без утверждения о причине, вероятности или качестве при неизвестной
  происхождении климатологии.
- [ ] Сделать JSON-адаптер `analyze` как прототип общего контракта: значение,
  observed/imputed, метод, причина и ограничения. Веб-вход и пакетный вход остаются
  разными командами над общими функциями.
- [ ] Начать `reports/experiments.csv` и журнал условий baseline; не заполнять
  RMSE или Gap Score выдуманными числами.

**Готово локально:** базовый метод, пакетная команда, точный валидатор ключей,
z-score и JSON-прототип проходят синтетическую фикстуру, включая полностью
пропавший полигон и края ряда.
**Готово на данных:** submission строится только после выдачи private CSV; это
отдельная проверка от локального синтетического результата.

## ML-03 — сравнение методов и оценка восстановления (6–18 ч)

**Статус:** planned

**Владелец:** ML. **Зависимости:** ML-01/02 и фактические CSV для оценки;
B4 параллельно готовит ограниченный запуск Python.

- [ ] На одинаковых отложенных группах сравнить базовый метод, линейную интерполяцию
  по времени и одного CPU-регрессора. PCHIP рассмотреть только как дополнительный
  ограниченный эксперимент, если остаётся время. Нейросеть не
  обязательна. Не смешивать строки одного gap между обучением и проверкой.
- [ ] Синтетическую маску применять ко всем динамические/производные полям, пересчитывая
  признаки после маски; retrospective validation может использовать известные
  соседи с обеих сторон. Local holdout complete polygons/seasons — командный
  протокол, а не обязательное правило организаторов.
- [ ] Считать RMSE по всем контрольным строкам как RMSE по объединённым контрольным точкам, а не среднее
  RMSE по полигонам. Gap Score считать только по формуле
  `round(30 * max(0, 1 - RMSE / 0.10), 2)`.
- [ ] Отдельно назвать локальную синтетическую/отложенную оценку и официальный
  платформенный score по скрытым контрольным строкам. Не выдавать локальную оценку за
  результат платформы и не заявлять успех до фактического запуска.
- [ ] Выбрать метод только по сопоставимым результатам, сохранить seed,
  параметры, версии, missingness, группы holdout и ошибочные случаи. Если данные
  недоступны, оставить протокол и записать блокирующую зависимость данных без
  статуса завершения.

**Готово:** есть воспроизводимое сравнение на реальных данных с локальной маской;
выбранный метод не использует запрещённые признаки или скрытые цели, а валидатор
подтверждает точный набор контрольных ключей. Ожидание данных сохраняется как
блокер незавершённого этапа.

## ML-04 — веб-анализ и сквозной мост (8–12 ч)

**Статус:** planned

**Владельцы:** ML — функции, два Python-входа и зависимости; B4 — Go subprocess,
и Docker; B3 — пользовательский контракт; frontend — отображение.
**Зависимости:** JSON-прототип ML-02 и минимальный Go job path.

- [ ] Довести отдельную веб-команду анализа нового полигона: исходные наблюдения,
  восстановленный ряд, базовый z-score, статус, численные основания и причины
  ограничений. Никакого общего поля `confidence`, пока оно не калибровано.
- [ ] Batch-команда и веб-команда вызывают одни функции восстановления/аномалий,
  но принимают разные контракты и режимы доступности признаков.
- [ ] Передать JSON через stdin/stdout фиксированного Python-модуля; B4 задаёт
  timeout, размер ввода/вывода и число параллельных задач, без shell и HTTP.
- [ ] Проверить простой веб → Go → Python → Go результат к 12-му часу на
  фикстуре и реальном ряду от сборщика B1; отдельно показать ошибку
  источника и недостаток контекста. Не считать фикстуру доказательством качества
  на скрытом тесте.
- [ ] Описать сопоставление `primary_ndvi`, доступность спутниковых/погодных признаков и резервный
  метод для случая, когда веб-провайдер не даёт обучающие признаки.

**Готово:** сквозной JSON вызывается ограниченной задачей, исходное и
восстановленное значение различимы, а веб и пакетный режим воспроизводимы по README.

## ML-05 — расширенные аномалии, объяснение и перенос (18–28 ч)

**Статус:** planned

**Владелец:** ML с B1, B3 и frontend. **Зависимости:** ML-04 и подтверждённое
происхождение климатологии и погодных признаков.

- [ ] Уточнить детектор аномалий на z-score относительно той же сезонной фазы. Базовый пример
  фиксирует `z >= -1` как normal, `-2 <= z < -1` как biomass stress, `z < -2`
  как critical; альтернативу принять только с обоснованием и локальной проверкой.
- [ ] Хранить отдельно четыре UX-статуса `normal`, `candidate`, `confirmed`,
  `insufficient_data` и severity. Низкое качество, малое число наблюдений и
  собственная импутация не подтверждают причину события.
- [ ] Выводить погодную гипотезу только вместе с наблюдаемыми основаниями и
  ограничениями; показывать наблюдения и восстановленные значения разными маркерами.
- [ ] Проверить длинные пропуски, частичные признаки и новый регион. Исторический
  сценарий может использовать оба соседних края; разработка ранних онлайн-оповещений
  в эти 48 часов не входит.
- [ ] Передать frontend поля для графика, сезонного фона, величины отклонения,
  severity, статуса и ограничений объяснения.

**Готово:** синтетические и реальные случаи дают объяснимые периоды;
причинные гипотезы явно отделены от фактов, а переносимость проверена на
согласованном втором регионе. Ожидание источника не закрывает этап.

## Открытые зависимости

Фактические `train_dataset.csv` и `private_features.csv` ещё не переданы в эту рабочую папку; поэтому
число строк, схема, RMSE по объединённым контрольным точкам, Gap Score, выбранный метод и абляции требуют
подтверждения. Окончательные сопоставления провайдеров, происхождении климатологии,
доступность спутниковых/погодных признаков и параметры источников также неизвестны. Эти
неопределённости фиксируются в журнале и отчёте, но не являются основанием
придумывать данные или объявлять этап завершённым.
