## 2. Маршрутизация и раздача статики

- Go отдаёт `frontend/dist` из `/app/public`. SPA-fallback (все пути → `index.html`) **не обещан**.
- Поэтому **один маршрут `/`**. Всё состояние в query-параметрах: `?area=&event=&date=&mock=1`.
- Никаких client-side путей (`/app`, `/dev/states` как отдельного URL). Страница состояний для разработки — через `?dev=states` и только при `import.meta.env.DEV`.
- Если B4 подтвердит SPA-fallback — разрешено вернуть `/app`. До подтверждения — нет.

## 3. Требования сборки и CI (из общего плана команды)

- Пакетный менеджер: **npm**. `frontend/package-lock.json` обязательно закоммичен — CI кеширует по нему.
- Обязательные скрипты в `package.json`:
  - `npm run dev`
  - `npm run typecheck` — `tsc --noEmit`
  - `npm run lint`
  - `npm run test` — vitest, без watch
  - `npm run build` — результат строго в `frontend/dist`
- CI выполняет из `frontend/`: `npm ci && npm run typecheck && npm run build`. Всё должно проходить без сети к бэкенду и без переменных окружения.
- Docker context — корень репозитория; Dockerfile для Go-образа пишет B4, frontend только гарантирует воспроизводимый `npm ci && npm run build`.
- `VITE_API_URL` по умолчанию **пустая строка** (same-origin: фронт и API отдаёт один Go-контейнер). Не хардкодить `localhost:8080`.
- `VITE_MOCK=1` или `?mock=1` включает MSW. В production-сборке MSW-воркер подключается только при `?mock=1`.
- Версии runtime зафиксированы: Node 22 LTS (`.nvmrc` / `engines`), версии пакетов — из `frontend-plan.md` §1.

## 4. Приоритеты и сокращения (48 часов)

- P0 на моках: FE-0 … FE-5. Цель — рубеж 8–12 ч.
- FE-6: axe однократно; Playwright — один smoke desktop + один smoke mobile, не e2e на каждый этап.
- FE-7: только после получения от B3 живого API или согласованных примеров ответов.
- Тесты обязательны для: адаптеров (`src/api/adapters/*`), `lib/series.ts` (`splitByProvenance`), `lib/geo.ts`. Остальное — по остатку времени.
- Storybook не ставить; страница состояний `?dev=states` достаточна.
- Вне scope: аккаунты, уведомления, AI-чат, загрузка CSV, обучение модели, текстовый поиск места, экспорт, сравнение участков, тёмная тема.

## 5. Общие правила проекта

- Комментарии к нетривиальному коду — **на русском**.
- Frontend не вычисляет ничего из области анализа: ни z-score, ни статусы, ни отклонения, ни сезонный фон.
- Отсутствующее значение → «Нет данных» (`null` никогда не рисуется как 0). Отсутствующее необязательное поле → строка скрыта.
- Статус задачи, вывод анализа и тяжесть — три независимых поля с отдельными подписями.
- Никаких выдуманных процентов прогресса, ETA, вероятностей, доверительных интервалов.
- Все строки интерфейса — только из `src/lib/labels.ts`.
- Фикстуры моков помечены `_synthetic: true`, в UI при mock-режиме виден бейдж «Демонстрационные данные».
- Расхождения с реальным контрактом фиксируются в `frontend/.agent/ui-spec.md`, раздел 8, с указанием владельца.
